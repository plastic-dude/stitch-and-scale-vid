## Research decision

RFC 3464 defines delivery-status notifications as reports about the result of an attempt to deliver a message and distinguishes delivery processing from later human understanding or action.[381] W3C requires clear user feedback about form submission success or errors but does not treat interface feedback as a remote recipient receipt.[382] CYC emphasizes recipient/contact/project submission context without defining acknowledgement semantics.[383] Internal contracts preserve recipient/source/date, handoff context, privacy, rights, local-first persistence, and distinct human evidence gates.[388] Current platform and caption guidance supports a short vertical master with human-reviewed captions.[384] [385] [386] [387] None of this proves current Stitch & Scale acknowledgement-state behavior.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | One handoff moving from sender action to uncertain recipient disposition. |
| Desire | To know exactly what has happened without overclaiming receipt or agreement. |
| Obstacle | Sent, delivered, opened, acknowledged, understood, and actioned are different events. |

| Escalation | Draft → sent → delivered? → opened? → acknowledged → understood/responded → actioned → proof or open state. |
| Final image | `RECEIPT STATUS VISIBLE — RECIPIENT ACTION NOT ASSUMED`. |

## Difference from nearest prior angle

The nearest prior angle is `submission-state`, which distinguishes a submitted project from acceptance, contract, publication, or rights transfer. `ack-state` changes the pain to **a handoff being treated as received, understood, or actioned when only the sender’s transmission is known**. The hook changes to **“Sent is not acknowledged.”** The visual metaphor changes from an editorial lifecycle to a handoff card moving through `DRAFT → SENT → DELIVERED? → OPENED? → ACKNOWLEDGED → UNDERSTOOD/RESPONDED → ACTIONED`. The proof surface changes from project submission context to transport/disposition/response fields. The emotional turn changes from separating submission outcomes to honest uncertainty about what another person has actually received or done. The final line changes to **“Name the receipt before you call it received.”**

It is distinct from `next-owner` because it is not next-action ownership; from `reader-handoff` because it is not handoff readability/context; from `before-download` because it is not pre-download context; from `quote-permission` because it is not public reuse rights; from `focus-path` because it is not UI reachability; and from `conflict-state` because it is not disagreement between records. It does not reopen or reuse `false-completion` or `release-gate-roster`.

## Treatment and production bible

Open on an original abstract card marked `ILLUSTRATIVE — NOT PRODUCT UI`: `HANDOFF: TEST-KNIT NOTES`. A small sender-side stamp reads `SENT AT 23:00`. The card then asks `DELIVERED?`, `OPENED?`, `ACKNOWLEDGED BY/AT`, `UNDERSTOOD OR RESPONSE`, and `ACTION STATUS`. The narrator refuses to equate a local success message or transport result with a human acknowledgement. A final card reads `RECEIPT STATUS VISIBLE — RECIPIENT ACTION NOT ASSUMED`.

A current Stitch & Scale handoff capture may replace fictional cards only if a current, approved, non-private proof registry entry verifies exact sent/delivered/opened/acknowledged/understood/action fields, channel semantics, recipient privacy, and rights to show the capture. A screenshot cannot prove a recipient understood, agreed, or acted; product/data evidence is required. If proof is absent, retain the blocker card and disclaimer.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover handoff labels, timestamps, recipient/status fields, proof, hands, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product labels or receipt evidence.
