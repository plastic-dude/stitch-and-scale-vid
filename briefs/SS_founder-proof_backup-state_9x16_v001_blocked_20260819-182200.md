## Concept and distinctness

A copy may exist without proving that it is current, intact, accessible, or restorable. The nearest prior angle is `retention-state`, which focuses on why stored material remains and how its purpose, basis, review, access, disposal, and exceptions are bounded. `backup-state` changes the pain to a copy being treated as recoverable without a scope, snapshot, integrity check, restore test, recovered state, or recovery objective record. The hook becomes “A backup is not a restore.” The visual metaphor changes from a purpose-to-review retention timeline to a backup-to-recovery test path. The proof surface is `BACKUP ID / SCOPE / SNAPSHOT AT / STORAGE LOCATION / INTEGRITY CHECK / RESTORE TEST AT / RECOVERED STATE / RPO / RTO / OWNER / STATUS`. The emotional turn is from making continued storage answerable to confronting whether a copy can actually return the work. The final line is “Name the restore test before you call it recoverable.” It does not recreate retention-state, withdrawal-state, consent-state, recovery-path, access-scope, response-state, outcome-proof, provenance-chain, false completion, release roster, or a human release checklist.
