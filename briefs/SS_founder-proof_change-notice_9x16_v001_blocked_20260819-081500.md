## Campaign assumption

No active human brief was present in the refreshed repository. This run assumes founding-tester recruitment through the free demo and early-access cohort remains the campaign objective. The film is a year-round story about an active test, not a seasonal deadline announcement. It invites designers to inspect one current version-diff, change notice, milestone update, revision summary, or tester re-acknowledgement surface if proof is supplied; it does not promise that Stitch & Scale provides any of those behaviors.

## Research decision

GOV.UK Design System guidance warns that users can miss notification banners and recommends placing task-relevant information in the main content rather than relying on peripheral notices. Yarnpond documents a test workflow where updated pattern versions notify testers, milestone dates can move, and testers track progress. Edie Eckman’s Q&A stresses deadlines, gauge, photos, issue reporting, and the distinction between test knitting, sample stitching, and technical editing. These sources support the audience pain but do not prove Stitch & Scale’s product capabilities.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | A test already in progress receives a new version, requirement, milestone, or deadline. |
| Desire | The maker wants to know what changed, what remains valid, and whether continuing is still an informed choice. |
| Obstacle | A new file or changed date can arrive without an impact statement, preserved prior context, or a clear next decision. |
| Stakes | More labor may be requested under changed terms; no legal, financial, or product outcome is claimed. |
| Change | The fictional card becomes `WHAT CHANGED / WHAT REMAINS VALID / NEXT DECISION`. |
| Contradiction | “Latest” does not automatically explain “different.” |
| Escalation | New version appears → changed field is isolated → prior work is named → impact is stated → continue, pause, or ask remains a human decision. |
| Final image | A fictional change card with `REVIEW BEFORE CONTINUE`; no automatic alert, recheck, or consent badge. |

## Difference from nearest prior angle

The nearest prior angle is `correction-trace`, which focuses on locating a post-release correction and identifying which copy carries it. `change-notice` moves earlier and centers an active test participant deciding whether a new ask affects work already underway. The hook changes to **“A new version is a new ask until you show what changed.”** The visual metaphor changes from an old copy traveling toward a current correction record to a test card splitting into **`VERSION / CHANGE / IMPACT / CONTINUE?`**. The proof surface changes from version/errata history to a current version-diff, change notice, milestone update, revision summary, or tester re-acknowledgement surface. The emotional turn changes from accountable maintenance after release to agency before continuing labor. The final line changes to **“Show what changed before you ask for more.”**

It is distinct from `as-of` because it is not merely currentness labeling; from `event-window` because it is not deadline pressure against a calendar; from `feedback-loop` because it is not a response after a note; from `brief-before-knit` because work has already begun; from `first-record` because it is not an empty-state meaning problem; from `correction-trace` because it is pre-release and impact-oriented; from `hands-busy` because it is not interruption or return; from `credit-line` because it is not permission or attribution; and from imported `false-completion` and `release-gate-roster` because it is not generic completion or roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.

## Treatment and production bible

Open on a neutral tabletop with an original fictional card labeled `ILLUSTRATIVE — NOT PRODUCT UI`. A new version stamp appears beside an old test card. The card refuses to celebrate the update; instead, it asks three readable questions: `WHAT CHANGED?`, `WHAT REMAINS VALID?`, and `NEXT DECISION: CONTINUE / PAUSE / ASK`.

A real Stitch & Scale screen may replace the fictional card only if a current, approved, non-private capture or proof-registry entry verifies the exact surface, labels, product version/date, and rights to show it. If proof is absent, retain the blocker card and disclaimer. No real tester name, private message, test photo, pattern page, deadline, or personal data may appear without scoped permission. Do not imply automatic notification, rechecking, or consent capture.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover hands, proof cards, version labels, dates, numbers, buttons, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product proof.
