## Concept and distinctness

Permission for one capture or distribution context does not silently authorize every later use. The nearest prior angle is `waiver-state`, which focuses on a bounded deviation being mistaken for satisfaction of a requirement. `consent-state` changes the pain to permission being treated as blanket rights across purposes, uses, storage, derivatives, distribution windows, territories, platforms, or promotion. The hook becomes “Permission is not blanket consent.” The visual metaphor changes from a requirement/deviation card to a granular consent/rights card with the original purpose and use still visible. The proof surface is `SUBJECT / PURPOSE / USE / STORAGE / DISTRIBUTION / DERIVATIVE USE / VERSION / GIVEN AT / WITHDRAWN AT / STATUS`. The emotional turn is from preserving what remains unmet to narrowing what is actually permitted. The final line is “Name the use before you call it consent.” It does not recreate waiver-state, rights-scope, quote-permission, feedback-permission, capture-freshness, review-expiry, exception-scope, provenance-chain, evidence-coverage, false completion, release roster, or a human release checklist.
