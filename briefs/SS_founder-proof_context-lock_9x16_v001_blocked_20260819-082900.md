## Research decision

GOV.UK design principles emphasize understanding the context in which people use services. MOJ guidance shows how an interruption can explain that one changed answer affects other sections and require an intentional acknowledgement before continuing. W3C guidance emphasizes that important status changes should be communicated accessibly without unnecessarily moving focus and with enough context to understand the update. The repository’s mobile-maker contract requires project, size, units, unsaved state, validation result, and route-back context to remain visible. None of these sources proves Stitch & Scale has a context lock, sync, interruption card, or recovery behavior.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | A designer returns to a number after switching project, size, unit, or device. |
| Desire | To know which record and measurement context is active before making or trusting an edit. |
| Obstacle | The same-looking field can mean a different project, size, or unit when context is hidden or assumed. |
| Stakes | A designer may edit or interpret the wrong record; no actual product error or customer outcome is claimed. |
| Change | The fictional strip makes `PROJECT / SIZE / UNIT / EDITING` explicit before the number. |
| Contradiction | The dangerous part is not the number; it is the unspoken context around it. |
| Escalation | Number appears → project ambiguity → size/unit ambiguity → active context confirmed → human decides whether to edit. |
| Final image | A fictional context strip above a number with `CHECK ACTIVE CONTEXT`; no lock, sync, or recovery badge. |

## Difference from nearest prior angle

The nearest prior angle is `size-boundary`, which focuses on the limits of the size range and honest coverage. `context-lock` changes the pain to **the same field meaning different things when project, size, or unit context is unclear**. The hook changes to **“The dangerous part is not the number. It is which number you are editing.”** The visual metaphor changes from a boundary line around supported sizes to a context strip **`PROJECT / SIZE / UNIT / EDITING`** that must be confirmed before a number is trusted. The proof surface changes from coverage boundaries to a current active-context header, project/size/unit indicator, unsaved-state marker, route-back surface, or context-change checkpoint. The emotional turn changes from knowing the limits of a size range to quiet confidence in the active record. The final line changes to **“Name the context before you trust the number.”**

It is distinct from `hands-busy` because it is not interruption during physical work; from `offline-continuity` because it does not claim offline persistence or recovery; from `first-record` because it is not an empty-state meaning problem; from `change-notice` because it is not a mid-test revision; from `measurement-moment` because it is not measurement capture; from `repro-note` because it is not issue-report context; from `locale-drift` because it is not translation drift; and from imported `false-completion` and `release-gate-roster` because it is not completion or roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.

## Treatment and production bible

Open on a neutral tabletop with an original fictional card labeled `ILLUSTRATIVE — NOT PRODUCT UI`. A large number appears without context. The frame asks, quietly: `WHICH PROJECT?`, `WHICH SIZE?`, `WHICH UNIT?`, `WHAT ARE YOU EDITING?` The number remains unchanged; the context strip is what changes. The final card reads `CHECK ACTIVE CONTEXT` rather than `LOCKED`, `SYNCED`, or `RECOVERED`.

A real Stitch & Scale screen may replace the fictional card only if a current, approved, non-private capture or proof-registry entry verifies the exact surface, labels, product version/date, and rights to show it. If proof is absent, retain the blocker card and disclaimer. No real project name, private record, device screenshot, tester data, or current UI label may appear without approval. Do not imply device sync, automatic recovery, or context protection.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover hands, context cards, numbers, buttons, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product proof.
