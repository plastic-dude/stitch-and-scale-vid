## Research decision

GOV.UK Design System guidance distinguishes settings where a preselected default may be appropriate from questions where preselection can influence an answer. Its check-answers pattern supports a second review before confirmation, clear action wording, Change links, and explicit `Not provided` for skipped optional answers. These sources support exposing origin and confirmation state, but they do not prove Stitch & Scale exposes default provenance, inherited values, confirmation states, or check-answers behavior.

## Concept and dramatic engine

| Engine element | Director decision |

| Subject | A visible value sits in a form or record before a designer decides whether to trust it. |
| Desire | To know whether the value was chosen, inherited, defaulted, or left unprovided. |

| Stakes | A designer may publish or calculate from an assumption; no actual product outcome is claimed. |

## Difference from nearest prior angle

The nearest prior angle is `basis-label`, which focuses on whether a value is measured, estimated, planned, or derived. `default-state` changes the pain to **whether the value’s origin is a system starting point, an inherited record, an active user choice, or an absent answer**. The hook changes to **“A filled field is not a confirmed choice.”** The visual metaphor changes from measurement basis cards to **`DEFAULT / INHERITED / USER CONFIRMED / NOT PROVIDED`**. The proof surface changes from value-status/provenance to a current default marker, inherited-value label, changed-versus-unchanged state, confirmation/check-answers surface, explicit `Not provided`, or source-of-value field. The emotional turn changes from epistemic humility about what a number means to deliberate confirmation before consequential use. The final line changes to **“Name the origin before you trust the choice.”**

It is distinct from `basis-label` because it is choice origin rather than value type; from `context-lock` because it is not which record is active; from `first-record` because it is not whether a record exists; from `artifact-status` because it is not copy identity; from `delete-scope` because it is not destructive consequence; and from imported `false-completion` and `release-gate-roster` because it is not completion or roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.
