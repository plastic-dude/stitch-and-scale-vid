## Campaign assumption

No active human brief was present in the refreshed repository. This run assumes founding-tester recruitment through the free demo and early-access cohort remains the campaign objective. The film is a year-round local-record story, not a data-loss scare or urgency message. It invites designers to inspect one current delete confirmation, affected-record summary, dependency warning, unlink-versus-delete choice, or undo/restoration surface if proof is supplied; it does not promise that Stitch & Scale provides any of those behaviors.

## Research decision

GOV.UK’s design-system backlog frames confirmation as appropriate for serious or irreversible actions and records a discussion that undo may be friendlier where possible. MOJ guidance shows how an interruption can explain consequences before a user continues. The craft-business and mobile-maker contracts require preserving history, distinguishing source records from derived rollups, naming the affected record, confirming destructive deletion, and preserving unrelated records. None of this proves Stitch & Scale has a delete preview, undo, restoration, or dependency-warning surface.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | A designer is about to delete a source record. |
| Desire | To remove exactly what is intended without silently erasing history or confusing a derived total with its source. |
| Obstacle | `DELETE`, `REMOVE FROM VIEW`, and `UNLINK EVIDENCE` can sound similar while having different consequences. |
| Stakes | A source record, linked evidence, or derived understanding may be lost; no actual product outcome is claimed. |
| Change | The fictional consequence card names the affected record, linked evidence, derived view, and cancel path. |
| Contradiction | A red button can signal danger without explaining the scope. |
| Escalation | Generic `DELETE` → named source → possible derived effect → explicit choice → human confirmation. |
| Final image | A fictional card with `AFFECTED RECORD / WHAT CHANGES / WHAT STAYS / CANCEL`; no `UNDO AVAILABLE` badge. |

## Difference from nearest prior angle

The nearest prior angle is `recovery-proof`, which focuses on proving restoration after loss or interruption. `delete-scope` moves earlier to the decision boundary before destruction and asks what exactly leaves, what remains, and which derived view may change. The hook changes to **“Delete the record, not the story around it.”** The visual metaphor changes from a restored workspace to a source record splitting into **`DELETE / REMOVE FROM VIEW / UNLINK EVIDENCE`**. The proof surface changes from recovery evidence to a current delete confirmation, affected-record summary, dependency warning, unlink-versus-delete choice, or undo/restoration surface. The emotional turn changes from relief after recovery to confidence through named consequences before deletion. The final line changes to **“Name what leaves. Name what stays.”**

It is distinct from `offline-continuity` because it is not offline persistence; from `context-lock` because it is not active project/size/unit context; from `first-record` because it is not an empty state; from `data-minimum` because it is not data collection restraint; from `sample-chain` because it is not physical custody; from `change-notice` because it is not a version update; and from imported `false-completion` and `release-gate-roster` because it is not completion or roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.
