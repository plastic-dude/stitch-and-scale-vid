## Research-informed premise

Craft Yarn Council’s current designer-pitfalls guidance warns against writing from memory, incomplete instructions, missing abbreviations, omitted counts or repeats, missing charts and schematics, and making changes in a contracted project without prior permission. [1] Its current project checklist separates notes, yarn and dye-lot confirmation, sample size, gauge, electronic instructions, printout, measurements, charts, schematic, invoice, contract, and return shipping. [2] Knitty’s current June 17, 2026 submission guidance separates proposal, sample, completed pattern, acceptance, technical editing, test knitting, and publication. [3] These sources support a bounded edit-boundary question, not an automatic product feature claim.

Git’s current user manual describes changes as history represented by commits, with branches and tags as references to commits. [4] This is only a documentary analogy; it does not prove that Stitch & Scale uses Git, exposes history, detects changes, protects releases, or routes re-review.

## Dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | Fictional source card moving through editable, reviewed, and released states. |
| Desire | Make a necessary revision without erasing the record or silently changing a released copy. |
| Obstacle | One file can look writable while its review or release context is invisible. |
| Stakes | A changed source may be mistaken for an unchanged reviewed artifact; no actual failure is claimed. |
| Change | A pencil stops at the released-copy boundary and creates a new revision card marked `RE-REVIEW REQUIRED`. |
| Contradiction | Editable does not mean safe to change without consequence. |
| Escalation | Editable source → reviewed snapshot → released copy → attempted edit → new revision/re-review card. |
| Final image | `EDITABLE SOURCE / REVISION 02` beside `RELEASED COPY / DO NOT EDIT IN PLACE` and `RE-REVIEW REQUIRED`. |

## Treatment, beats, and visual grammar

Use one unbranded tabletop, one source card, one revision card, one reviewed snapshot, and one released-copy card. The opening source card reads `SOURCE / REV 02 / EDITABLE? UNVERIFIED` and is visibly illustrative. A pencil line moves toward `RELEASED COPY`; the hand pauses, then creates `REV 03 / CHANGE REASON / RE-REVIEW REQUIRED`. The film does not show a green approval state or imply a live product screen.

| Time | Beat | Image and action | Spoken idea | Evidence status |
|---:|---|---|---|---|
| 0–5s | Writable illusion | `EDITABLE?` card beside a pencil. | “Editable is not the same as safe to change.” | General workflow principle. |
| 5–12s | State separation | `EDITABLE SOURCE`, `REVIEWED SNAPSHOT`, `RELEASED COPY`. | “The source, the reviewed snapshot, and the released copy are not automatically the same thing.” | Illustrative distinction. |
| 12–20s | Permission boundary | Pencil stops at `WHO MAY CHANGE IT?` / `EDIT SCOPE?`. | “Before you change a line, name who may change it and which copy they are touching.” | CYC permission and record guidance. |
| 20–29s | History | New card `REV 03 / CHANGE REASON / SOURCE: REV 02`. | “Keep the earlier state visible. A new revision is not proof that the old review still applies.” | Source-history analogy; no Git claim. |
| 29–37s | Re-review trigger | `RE-REVIEW IF CHANGED` beside separate human gates. | “If the change reaches the math, chart, schematic, print, or test-knit evidence, review that gate again.” | Human gates remain separate. |
| 37–45s | Honest ending | Final boundary card. | “Name what you changed—and what must be reviewed again.” | Blocked; no product capability claim. |

## Exact script

**0–5 seconds:** “Editable is not the same as safe to change.”

**5–12 seconds:** “The source, the reviewed snapshot, and the released copy are not automatically the same thing.”

**12–20 seconds:** “Before you change a line, name who may change it and which copy they are touching.”

**20–29 seconds:** “Keep the earlier state visible. A new revision is not proof that the old review still applies.”

**29–37 seconds:** “If the change reaches the math, chart, schematic, print, or test-knit evidence, review that gate again.”

**37–45 seconds:** “Name what you changed—and what must be reviewed again.”
