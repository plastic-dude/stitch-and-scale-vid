## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | One baseline rule and one local exception attached to a specific item/size. |
| Desire | To apply a special case without accidentally changing every case. |
| Obstacle | Scope, reason, review/expiry, ownership, and approval can disappear when the exception is recorded as a bare value. |
| Stakes | A local adjustment may be copied into other sizes or projects; no real defect or outcome is claimed. |
| Change | The fictional record adds affected item/size, scope, reason, effective/review dates, owner, approval, and status. |
| Contradiction | An exception can be useful precisely because it is not general. |
| Escalation | Baseline → exception → affected scope → reason → effective/review → owner/approval → status → generalization warning. |
| Final image | `LOCAL EXCEPTION — GENERAL RULE UNCHANGED`. |

## Difference from nearest prior angle

The nearest prior angle is `default-state`, which separates a default suggestion from a committed value. `exception-scope` changes the pain to **a local adjustment being silently treated as a general rule for every size, item, or project**. The hook changes to **“An exception is not the rule.”** The visual metaphor changes from default/committed cards to a baseline rule with one scoped exception bracketed to a specific size/item, followed by reason, effective/review, owner, approval, and status cards. The proof surface changes from default semantics to bounded exception context. The emotional turn changes from avoiding uncommitted defaults to preventing scope leakage. The final line changes to **“Name the scope before you generalize the exception.”**

It is distinct from `value-state` because it is not null/zero/invalid semantics; from `size-boundary` because it is not the range boundary; from `substitution-basis` because it is not substitute reasoning; from `impact-scope` because it is not downstream propagation; from `decision-ledger` because it is not decision rationale generally; from `supersession-state` because it is not predecessor replacement; and from `conflict-state` because it is not disagreement. It does not reopen or reuse `false-completion` or `release-gate-roster`.
