## Research decision

Microsoft distinguishes formula precedents from dependents and documents tracing those relationships across levels.[324] NIST’s Map function emphasizes documenting context, assumptions, limitations, and potential impacts.[325] A current knitwear grading workflow separates measurements, gauge, ease, units, formulas, and derived counts.[326] W3C separates missing/invalid input from downstream correction suggestions,[327] [328] and missing-data research warns that filling absent data can create uncertainty.[329] Current platform and caption guidance supports a short vertical master with human-reviewed captions.[330] [331] [332] [333] Stitch & Scale’s internal contracts separate source inputs, derived views, records, estimates, technical edit, print review, chart, schematic, and test-knit evidence.[334] None of this proves current product dependency behavior.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | One changed source input and the set of downstream outputs that may be affected. |
| Desire | To know the review boundary before trusting a revised number or export. |
| Obstacle | A source field may feed multiple size counts, measurements, quantities, charts, or exports whose impact is not visible. |
| Stakes | A designer may review one number while another dependent output remains unknown; no real defect or outcome is claimed. |
| Change | The fictional record changes from one changed input to a bounded impact map with affected scope and recheck state. |
| Contradiction | A change can be small at the source and large in its downstream review surface. |
| Escalation | Source → changed value → dependent outputs → affected size/section → recheck → recompute status → proof or blocker. |
| Final image | `IMPACT SCOPE VISIBLE — PRODUCT PROOF REQUIRED`. |

## Difference from nearest prior angle

The nearest prior angle is `stale-number`, which focuses on one changed input leaving yesterday’s derived number inside instructions. `impact-scope` changes the pain to **knowing the set of dependent outputs touched by one changed source before trusting the revision**. The hook changes to **“One change can have a long shadow.”** The visual metaphor changes from one stale-value warning to an impact tree from one source input to affected sizes, sections, quantities, charts, and exports. The proof surface changes from one live derived value to a current source/dependent impact surface with affected-scope and recheck labels. The emotional turn changes from catching one stale number before release to bounded review of what a change touches. The final line changes to **“Show what the change touches before you trust the new number.”**

It is distinct from `change-notice` because it is not a communication event; from `correction-trace` because it is not post-release errata; from `artifact-status` because it is not copy identity; from `context-lock` because it is not active project/size/unit selection; from `repro-note` because it is not issue-report context; from `grade-transparency` because it is not why one size differs; from `value-state` because it is not the classification of one field; from `recovery-proof` because it is not restoration; from `export-portability` because it is not file transport; and from `quantity-basis` because it is not the basis of a quantity. It does not reopen or reuse `false-completion` or `release-gate-roster`.

## Treatment and production bible

A line branches to fictional dependent cards: `SIZE COUNTS / FINISHED MEASUREMENTS / YARDAGE / CHART / EXPORT`. Each dependent card receives a state: `CHECK / NOT CHECKED / NOT APPLICABLE / UNKNOWN`. The narrator refuses to promise that every downstream surface is known. A second card adds `AFFECTED SCOPE / RECHECK NEEDED / RECOMPUTE STATUS / SOURCE / DATE / OWNER / NOTES` before the final blocker card.

A still image cannot prove dependency graphs, recalculation, completeness, or export freshness; those require interaction/data evidence. If proof is absent, retain the blocker card and disclaimer.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover source cards, branch lines, dependent outputs, size labels, numbers, recheck states, hands, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product labels or dependency evidence.
