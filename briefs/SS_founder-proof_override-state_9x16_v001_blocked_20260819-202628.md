## Concept and distinctness

A manual exception can be useful without being a trusted correction. The nearest prior angle is `authority-state`, which concerns which populated source controls a value. `override-state` changes the pain to an exception silently becoming the new truth. The hook becomes “Overridden is not corrected.” The visual metaphor changes from source/derived/display/override dependency to a calculated value branching into an exception lane. The proof surface is `TARGET / ORIGINAL / OVERRIDE / REASON / SCOPE / EXPIRES / REVIEWER / AFFECTED OUTPUT`, explicitly illustrative until product proof exists. The emotional turn is from duplicate-data anxiety to bounded exception accountability. The final line is “Name the override before it becomes the rule.” It does not recreate `authority-state`, `input-state`, `waiver-state`, `tolerance-state`, `dependency-state`, `version-lock`, `priority-state`, imported `false-completion`, or imported `release-gate-roster`.
