## Campaign assumption

No active human brief was present in the refreshed repository. This run assumes founding-tester recruitment through the free demo and early-access cohort remains the campaign objective. The film is a year-round story about readiness before a step, not automatic blocking, gauge validation, or eligibility promise. It invites designers to inspect one current prerequisite checklist, ready/not-ready state, dependency notice, preflight panel, gauge/measurement readiness surface, or eligibility explanation if proof is supplied; it does not promise that Stitch & Scale provides any of those behaviors.

## Research decision

Craft Yarn Council advises reading the relevant pattern section, doing what it says, and using a gauge swatch before beginning. GOV.UK’s suitability-check pattern recommends helping users determine early whether a service is appropriate and presenting relevant information at the point it is needed. These sources support visible prerequisites and a human readiness check, but they do not prove Stitch & Scale detects prerequisites, validates gauge, blocks out-of-order work, or determines eligibility.

## Difference from nearest prior angle

The nearest prior angle is `sequence-map`, which focuses on where a maker moves through pattern sections and related documents. `prerequisite-state` changes the pain to **what must already be true before the next step is safe or meaningful to begin**. The hook changes to **“A step can be clear and still be too early.”** The visual metaphor changes from a route/sequence map to **`REQUIRED BEFORE / READY / NOT READY / WHY`**. The proof surface changes from navigation/sequence mapping to a prerequisite checklist, readiness state, dependency notice, preflight panel, gauge/measurement readiness surface, or eligibility explanation. The emotional turn changes from knowing where to go next to informed readiness without automatic blocking. The final line changes to **“Show what must be true before the step begins.”**

It is distinct from `sequence-map` because it is precondition rather than route; from `gauge-reality` because it is readiness visibility rather than gauge result; from `brief-before-knit` because it is step dependency rather than design intent; from `support-boundary` because it is a prerequisite state rather than a capability boundary; and from imported `false-completion` and `release-gate-roster` because it is not completion or roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.
