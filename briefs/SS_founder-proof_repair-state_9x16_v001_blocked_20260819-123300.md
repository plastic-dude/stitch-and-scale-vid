It invites designers to inspect one current approved issue-disposition surface if proof is supplied; it does not promise that Stitch & Scale provides that behavior.

## Research decision

CYC’s Knit 911 hub covers dropped/twisted, missing/extra-stitch, yarn, circular-needle, seam, and finishing troubleshooting, including scope-sensitive repair context.[225] Sister Mountain distinguishes tech editing, which identifies errors and returns corrections, from test knitting, which reports user experience and should not be expected to find major errors.[226] Stitch & Scale’s contracts keep defect notes, repro, correction, status, source/version, technical editing, print/chart review, and test knitting separate.[227] [228] These sources support an issue-disposition checklist, but do not prove Stitch & Scale diagnoses or repairs.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | A fictional issue card moves from observation to scope, action, recheck, and open risk. |
| Desire | To know whether a discovered issue is merely reported, acted on, or actually rechecked. |
| Obstacle | “Found,” “fixed,” and “verified” can collapse into one reassuring label. |
| Stakes | A maker may treat an unresolved issue as closed; no outcome is claimed. |

## Difference from nearest prior angle

The nearest prior angle is `error-language`, which focuses on how an error is worded. `repair-state` changes the pain to **what happened to a discovered issue after it was reported**. The hook changes to **“Found is not fixed.”** The visual metaphor changes from error labels to **`OBSERVED / SCOPE / ACTION / RECHECK / OPEN RISK / SOURCE / VERSION / STATUS`**. The proof surface changes from wording to a current issue-disposition surface. The emotional turn changes from naming the problem fairly to keeping its resolution status honest. The final line changes to **“Name what changed—and what is still open.”**

It is distinct from `count-check` because it tracks issue disposition rather than a numeric check; from `repro-note` because it includes action and recheck after reproduction; from `change-notice` because it distinguishes correction from verification; from `artifact-status` because it is an issue lifecycle rather than copy state; and from imported `false-completion` and `release-gate-roster` because it is not completion or evidence-roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.

## Treatment and production bible

Open on a neutral tabletop with an original abstract card marked `ILLUSTRATIVE — NOT PRODUCT UI`. A fictional issue begins as `OBSERVED`, expands to `SCOPE`, then `ACTION`, then `RECHECK`, while `OPEN RISK` stays visible until proof exists. `SOURCE / VERSION / STATUS` remain on the card. The end card reads `DISPOSITION VISIBLE — REVIEW OPEN`.

A real Stitch & Scale issue-disposition surface may replace the fictional card only if a current, approved, non-private capture or proof-registry entry verifies the exact surface, labels, product version/date, and rights to show it. If proof is absent, retain the blocker card and disclaimer. No diagnosis, repair recommendation, automatic correction, or verified-fix claim is permitted.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover issue fields, proof, tables, numbers, buttons, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product proof.
