## Campaign assumption

No active human brief was present in the refreshed repository. This run assumes founding-tester recruitment through the free demo and early-access cohort remains the campaign objective. The film is a year-round story about making tester observations inspectable, not a defect announcement or urgent support message. It invites designers to inspect one current issue-report, feedback-context, QA-note, version/size/gauge context, or evidence-attachment surface if proof is supplied; it does not promise that Stitch & Scale provides any of those behaviors.

## Research decision

GitHub and Atlassian’s current issue-report guidance emphasizes structured context, reproduction steps, expected versus actual results, environment or version information, evidence, and review for clarity. Edie Eckman’s Q&A adds knitwear-specific context such as gauge, instruction and diagram detail, photos, and immediate issue reporting while distinguishing test knitting, sample stitching, and technical editing. These sources support a context-rich tester note but do not prove Stitch & Scale has a tracker, issue template, or automated reproduction.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | A tester’s short observation that lacks enough context to inspect. |
| Desire | To make the observation useful without forcing the tester to write an essay or calling it a defect prematurely. |
| Obstacle | “Row 8 is wrong” does not identify version, project, size, gauge, expected result, observed result, or evidence. |
| Stakes | A human may chase the wrong issue, ask the tester to repeat work, or dismiss a real observation; no outcome is claimed. |
| Change | The fictional note becomes `VERSION / PROJECT / SIZE / GAUGE / ROW OR STEP / EXPECTED / OBSERVED / EVIDENCE`. |
| Contradiction | A longer note is not automatically a better note; the right context is better than more prose. |
| Escalation | Vague observation → missing context → compact fields → human inspection → no defect verdict without evidence. |
| Final image | A fictional report card with `OBSERVATION — NOT A DEFECT VERDICT`; no solved badge. |

## Difference from nearest prior angle

The nearest prior angle is `feedback-loop`, which focuses on what happens after feedback is received and routed. `repro-note` changes the pain to **a report that cannot be inspected without guessing because its context is missing**. The hook changes to **“A note is not reproducible until it carries its context.”** The visual metaphor changes from a note travelling through a response loop to a compact report card filling in **`VERSION / SIZE / GAUGE / ROW / EXPECTED / OBSERVED`**. The proof surface changes from feedback routing or response history to one current, approved issue-report, feedback-context, QA-note, version/size/gauge context, or evidence-attachment surface. The emotional turn changes from being heard after submission to making an observation actionable before anyone overclaims a defect. The final line changes to **“Keep the note. Keep the context.”**

It is distinct from `error-language` because it is not warning copy; from `correction-trace` because it is not locating a published correction; from `change-notice` because it is not disclosing a changed version; from `measurement-moment` because it is not capturing a measurement; from `count-check` because it is not verifying a count; from `decision-ledger` because it is not classifying a value; from `support-boundary` because it is not ownership of a support issue; and from imported `false-completion` and `release-gate-roster` because it is not completion or roster accountability. Neither imported concept is reopened, renamed, overwritten, or approved.

New readable slips attach to it: `VERSION`, `PROJECT`, `SIZE`, `GAUGE`, `ROW OR STEP`, `EXPECTED`, `OBSERVED`, and `EVIDENCE`. The last line says `OBSERVATION — NOT A DEFECT VERDICT`.

A real Stitch & Scale screen may replace the fictional card only if a current, approved, non-private capture or proof-registry entry verifies the exact surface, labels, product version/date, and rights to show it. If proof is absent, retain the blocker card and disclaimer. No real tester name, private message, photo, pattern file, project identifier, or personal data may appear without scoped permission. Do not imply automatic reproduction, defect detection, or routing.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover hands, proof cards, fields, numbers, buttons, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product proof.

## Exact script

**0–6s — Narrator:** “Row 8 is wrong.”

**6–15s — Narrator:** “Maybe. But which version? Which project? Which size? What gauge?”

**15–27s — Narrator:** “Keep the smallest context a human needs: row or step, expected, observed, and evidence.”

**27–34s — Narrator:** “That makes a note inspectable. It does not make it a defect verdict.”

**34–40s — Narrator:** “If Stitch & Scale shows a current context or issue surface, show exactly what it shows. If not, keep the claim open.”

**40–45s — Narrator:** “Keep the note. Keep the context.”
