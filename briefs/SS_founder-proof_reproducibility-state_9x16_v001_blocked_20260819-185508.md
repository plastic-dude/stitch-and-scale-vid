## Concept and distinctness

A second result that resembles the first can still come from different inputs, settings, versions, environments, or unrecorded decisions. The nearest prior angle is `version-lock`, which binds a claim to an exact artifact state. `reproducibility-state` changes the pain to whether a result can be rerun with the same inputs, settings, version, and environment, and whether the output comparison was actually reviewed. The hook becomes “Repeatable is not reproduced.” The visual metaphor changes from a claim anchored to a frozen snapshot to a replay lane with input, run, output, diff, and review states. The proof surface is `INPUT SNAPSHOT / VERSION / SETTINGS / RUN AT / OUTPUT / DIFF / ENVIRONMENT / REVIEWER / RESULT`, explicitly illustrative until product proof exists. The emotional turn is from “it looked right” confidence to inspectable replay confidence. The final line is “Name the run before you trust the repeat.” It does not recreate `version-lock`, `authority-state`, `absence-state`, `repro-note`, `measurement-provenance`, `conversion-trace`, `grade-transparency`, `outcome-proof`, `capture-freshness`, imported `false-completion`, or imported `release-gate-roster`.
