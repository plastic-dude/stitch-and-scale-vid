## Research-informed premise

The Craft Yarn Council’s current pattern-writing guidance gives testers concrete questions: are directions clear and concise; do abbreviations, symbols, and charts line up and match; is the materials list comprehensive and the yarn amount correct; and does the finished appearance match expectations? It distinguishes recording notes, transcription, standards, technical editing, and testing. [1]

These prompts support a record shape of `QUESTION`, `SUBJECT`, `SCOPE`, `EXPECTED EVIDENCE`, `RESPONSE`, and `FOLLOW_UP`. “Is this pattern good?” is not equivalent to “Do the chart symbols and written instructions match for size M, rows 1–12?”

Knitty’s current June 17, 2026 guidance expects completed submissions and distinguishes the designer’s work from technical editing, optional test knitting, editorial selection, rights, and publication. [2] W3C’s current WCAG 2.1 recommendation says success criteria are testable statements used for requirements and conformance testing; it also says accessibility requires automated testing and human evaluation and that even the highest conformance level cannot address every user need. [3] WCAG-EM 2.0 separates scope definition, representative sample selection, evaluation, and findings reporting, and warns that a selected subset generally does not support a whole-product conformance claim. [4]

## Dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | Fictional chart-review question card. |
| Desire | Make a review request that a human reviewer can answer without guessing what “done” means. |
| Obstacle | A vague `REVIEW?` card hides the subject, scope, criterion, evidence, and next action. |
| Stakes | A vague question can produce a confident-sounding response that does not answer the actual craft or accessibility issue. No real defect is claimed. |
| Change | The vague card splits into explicit question, subject, scope, expected evidence, response, reviewer, next check, and limit. |
| Contradiction | A question can be specific and still remain unresolved; unresolved is not failure, approval, or product detection. |
| Escalation | `REVIEW?` → question → subject/scope → expected evidence → response → next check/limit. |
| Final image | `QUESTION: SPECIFIC / RESPONSE: UNRESOLVED / HUMAN REVIEW REQUIRED`. |

## Treatment, beats, and visual grammar

Use one unbranded tabletop, one vague review card, one question card, one subject/scope rail, one expected-evidence card, one response card, one next-check card, and one limit card. All cards are original illustrative props. Open on a broad approval request and turn it into a bounded question without creating an approval cue.

| Time | Beat | Image and action | Spoken idea | Evidence status |
|---:|---|---|---|---|
| 0–5s | Vague request | `REVIEW?` beside fictional chart card. | “What exactly are you asking the reviewer to check?” | Fictional prompt only. |
| 5–12s | Question named | `QUESTION: DO CHART SYMBOLS MATCH WRITTEN ROWS 1–12?` | “Name the question.” | Concrete prompt, not a product claim. |
| 12–21s | Subject/scope | `SUBJECT: CHART C-01 / SCOPE: SIZE M / ROWS 1–12 / SCREEN VIEW`. | “Name the subject and scope.” | Bounded review model. |
| 21–30s | Evidence expected | `EXPECTED EVIDENCE: CHART KEY + WRITTEN ROWS + HUMAN CHECK`. | “Say what would count as evidence.” | No automated matching claim. |
| 30–38s | Response and next check | `RESPONSE: UNRESOLVED / REVIEWER: UNASSIGNED / NEXT CHECK: PRINT REVIEW`. | “An unanswered question is not an approval.” | Preserve human-gate boundaries. |
| 38–45s | Honest ending | `LIMIT: ONE REPRESENTATION / HUMAN REVIEW REQUIRED`. | “Ask the question the evidence can actually answer.” | Blocked; no capability claim. |
