## Concept and distinctness

A warning can be visible yet unusable if no condition says when it should change the next action. The nearest prior angle is `failure-mode`, which describes a scenario, initiating event, failure mode, effect, detection, and mitigation path. `risk-trigger` changes the pain to a warning being treated as actionable even though the event or threshold that should trigger a response is not defined. The hook becomes “A warning needs a trigger.” The visual metaphor changes from a full failure-mode path to a warning card with a missing trigger-to-action bridge. The proof surface is `OBSERVABLE / THRESHOLD-OR-EVENT / TRIGGER CONDITION / ACTION / OWNER / DEADLINE / STATUS / REVIEWED AT`. The emotional turn is from making failure visible to making response conditions explicit. The final line is “Name the trigger before you call it actionable.” It does not recreate failure mode, evidence type, evidence coverage, provenance chain, acceptance criteria, false completion, release roster, or a human release checklist.
