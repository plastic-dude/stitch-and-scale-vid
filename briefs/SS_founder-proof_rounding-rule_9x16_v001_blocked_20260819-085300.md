## Research decision

NIST GLP 9 says rounding should happen after the final expanded uncertainty is determined, that result and uncertainty should be rounded consistently, and that intermediate rounding can create errors in final results; it also says methods used should be documented. NIST’s broader metrology guidance separates traceability from fitness for purpose. The craft-business and mobile-maker contracts require units, active context, validation state, and readable records. None of this proves Stitch & Scale exposes conversion or rounding policy.

The nearest prior angle is `basis-label`, which focuses on whether a value is measured, estimated, planned, or derived. `rounding-rule` changes the pain to **the hidden transformation between an input and the displayed or used result**. The hook changes to **“The last decimal place can change the next instruction.”** The visual metaphor changes from value-status cards to a transformation strip **`INPUT / CONVERT / ROUND / USE`**. The proof surface changes from provenance or basis labels to a current unit-conversion display, rounding rule, calculation trace, intermediate-value view, precision control, or formula/method label. The emotional turn changes from basis humility to visible transformation before trust. The final line changes to **“Show the rule before you trust the rounded result.”**

It is distinct from `basis-label` because it is not value status; from `count-check` because it is not count parity; from `context-lock` because it is not active project/size/unit context; from `measurement-moment` because it is not measurement capture; from `locale-drift` because it is not translation or locale mismatch; from `decision-ledger` because it is not a decision record; and from imported `false-completion` and `release-gate-roster` because it is not completion or roster accountability.
