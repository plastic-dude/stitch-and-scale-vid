## Research decision

Craft Yarn Council’s current pattern-reading guidance explains asterisks for repeated steps, brackets and parentheses for grouped or repeated stitches, and examples such as “rep from *” or a specified repeat count. Proxmox’s current technical-writing guide says each procedural step should specify one clear action, answer “What should I do next?”, use sequence transitions, and state purpose before action. Neither source proves a current Stitch & Scale dependency graph, repeat checker, guided execution surface, or pattern-correctness validation.

The research changed the concept from generic instruction clarity into **dependency context before action**. The film must not claim guided execution, automated dependency checking, pattern correctness, or step completion.

## Campaign assumption

No active human brief was present in the checked repository state. This run assumes founding-tester recruitment remains the working objective through the free demo and early-access cohort. The film invites designers to inspect one verified setup, repeat, branch, sequence, or next-step surface; it does not promise that the product navigates or validates a pattern.

## Dramatic engine

| Element | Director decision |
|---|---|
| Subject | A next step is visible while its prerequisite, repeat scope, or branch condition remains hidden. |
| Desire | To let a maker know what must happen before the next action. |
| Obstacle | Short notation can compress setup, repeat, branch, and transition context into a line that looks complete. |
| Stakes | A maker can start the right-looking step at the wrong time or repeat the wrong scope. |
| Change | The viewer moves from “the next line is present” to “the dependency is visible before action.” |
| Contradiction | Showing sequence context can guide a reader without proving the pattern is correct or the step is complete. |
| Escalation | Instruction strip appears → `BEFORE / DO / REPEAT / THEN` split → branch line remains human-reviewed → no ready badge → current proof or blocker. |
| Final image | A fictional instruction strip beside `BEFORE / DO / REPEAT / THEN` and a pencil-marked branch. |

## Difference from prior concepts

The nearest prior angle is `notation-key`, which concerns local shorthand meaning and definition before decoding. `sequence-map` changes the pain to **a step being visible while its prerequisite, repeat scope, or branch condition remains hidden**; the hook to **“Before the next row, show what it depends on.”**; the visual metaphor from a terminology key to `BEFORE / DO / REPEAT / THEN` with a branch line; the proof surface from abbreviation/notation/key to setup/repeat/branch/sequence/next-step context; the emotional turn from generous definition to procedural orientation before action; and the final line to **“Show the next step’s reason.”**

It is distinct from `notation-key` because it is dependency context, not term meaning; from `reader-handoff` because it is step order, not document transfer; from `feedback-loop` because it is sequence, not response state; from `chart-parity` because it is repeat/branch structure, not chart-text equivalence; from `paper-proof` because it is instruction order, not medium change; from `design-intent` because it is what must happen next, not why the design was chosen; and from `false-completion`, `release-gate-roster`, `correction-trace`, `as-of`, `source-note`, `equivalent-meaning`, `readability-under-load`, `size-boundary`, `measurement-moment`, `gauge-reality`, `material-notes`, `care-context`, `sample-chain`, `technique-profile`, `support-boundary`, `brief-before-knit`, `permission-line`, `recovery-proof`, `decision-ledger`, `data-minimum`, `event-window`, `evidence-over-output`, `inherited-thread`, `offline-continuity`, and `locale-drift` because the conflict is action dependency before execution. It does not reopen, overwrite, rename, or consume the imported reservations.

## Treatment, visual grammar, and production bible

Open on an original fictional instruction strip labeled `ILLUSTRATIVE — NOT PRODUCT UI`: `SETUP 1 → [K2, P2] → REP? → NEXT`. A second line reads `BEFORE?`. Four cards appear: `BEFORE`, `DO`, `REPEAT`, and `THEN`. A “READY” or “STEP VERIFIED” badge is rejected. The branch is shown as a pencil line, not a computed dependency graph.

The product insert is optional and blocked until a current, versioned, non-private proof capture verifies exact setup, prerequisite, repeat, branch, sequence, next-step, or dependency labels. If absent, retain `SEQUENCE PROOF REQUIRED — NOT PRODUCT UI`. Any real pattern page, chart, test-knit record, person, or founder voice/image requires source and rights review. David may appear only with authorization and must be described only as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Use one narrator family. Captions must not cover instruction strips, branch lines, proof, hands, or CTA. Review caption-on and caption-free cuts.

## Exact script

**0–7s — Narrator:** “Before the next row, show what it depends on.”

**7–15s — Narrator:** “What must happen before this step? What repeats? Where does the branch begin?”

**15–25s — Narrator:** “One clear action is helpful. The context around it is part of the work.”

**25–31s — Narrator:** “A visible sequence can guide a reader. It cannot certify the pattern.”

**31–40s — Narrator:** “If Stitch & Scale shows a current sequence surface, show exactly what it shows. If not, keep the claim open.”

**40–45s — Narrator:** “Show the next step’s reason.”
