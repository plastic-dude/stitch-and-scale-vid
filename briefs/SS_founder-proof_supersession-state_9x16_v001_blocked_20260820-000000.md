## Research decision

Git documentation distinguishes replacing a local commit through amend from creating a new change that undoes prior work, and warns about rewriting pushed history.[389] NIST defines provenance as the chronology of origin, development, ownership, location, and changes to a system and associated data.[390] Vogue Knitting’s corrections page illustrates a publication practice of retaining a connection between corrections and past pattern context.[391] Internal contracts preserve stable IDs, provenance, version/date, local-first records, export identity, correction context, and distinct human evidence gates.[396] Current platform and caption guidance supports a short vertical master with human-reviewed captions.[392] [393] [394] [395] None of this proves current Stitch & Scale supersession behavior.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | A predecessor version or decision linked to a replacement. |
| Desire | To know what is current without erasing the record of what came before. |
| Obstacle | A new file or decision may hide the predecessor, effective boundary, reason, or affected scope. |
| Stakes | A designer may use the wrong copy or misunderstand what changed; no real outcome is claimed. |
| Change | The fictional record adds predecessor/new identity, supersedes link, effective-at, reason, scope, current status, owner, and source/date. |
| Contradiction | Replacement can be clear without pretending the predecessor never existed. |

| Final image | `CURRENT STATUS VISIBLE — PREDECESSOR NOT ERASED`. |

## Difference from nearest prior angle

The nearest prior angle is `correction-trace`, which links a released correction to reader-facing copy. `supersession-state` changes the pain to **new information being treated as a replacement while the predecessor, effective boundary, reason, scope, and current status disappear**. The hook changes to **“New does not erase old.”** The visual metaphor changes from an errata line connected to a published pattern to two version/decision cards connected by an explicit `SUPERSEDES` arrow with effective-at, reason, scope, owner, and current-status cards. The proof surface changes from correction linkage to predecessor/new identity and lifecycle context. The emotional turn changes from reader safety around corrections to historical clarity about what replaced what. The final line changes to **“Name what this replaces before you call it current.”**

It is distinct from `decision-ledger` because it is not decision rationale generally; from `change-notice` because it is not communication alone; from `artifact-status` because it is not which copy is held; from `capture-freshness` because it is not proof currentness; from `review-anchor` because it is not comment version/location; from `impact-scope` because it is not downstream propagation; from `submission-state` because it is not editorial lifecycle; and from `ack-state` because it is not handoff receipt. It does not reopen or reuse `false-completion` or `release-gate-roster`.
