## Research decision

W3C distinguishes omitted required input and invalid/out-of-range input and emphasizes identifying the affected field in text; it separately discusses correction suggestions.[314] [315] Research guidance explains that missingness has multiple causes and that imputation can create uncertainty if filled values are treated as observed facts.[316] WHO’s data-quality framework names missing values, measurement error, entry error, consistency, and fit-for-purpose review as separate concerns.[317] A current knitwear grading workflow keeps size, body measurement, gauge, units, ease, formula, and derived stitch/row counts distinct.[318] Current platform and caption guidance supports a sub-minute, vertical, human-reviewed master.[319] [320] [321] [322] Stitch & Scale’s internal contracts keep recorded, estimated, planned, calculated, technical, print, chart, schematic, and test-knit states separate.[323] None of this proves current product semantics.

## Concept and dramatic engine

| Engine element | Director decision |
|---|---|
| Subject | One field before it enters a calculation or record. |
| Desire | To know what a number means before trusting the next result. |
| Obstacle | Blank, zero, not applicable, invalid, planned, derived, and unverified states can look deceptively similar. |
| Stakes | A designer may make a decision from a value whose origin or status is unknown; no outcome is claimed. |
| Change | The fictional card changes from one ambiguous field to an explicit state, unit, source, date, validation, and notes record. |
| Contradiction | A blank field can be more honest than a plausible zero, but a blank can also mean “not applicable” or “not provided”; the state must be named. |
| Escalation | Field → value → state → source/date → validation → record/derived use → proof or blocker. |
| Final image | `VALUE STATE VISIBLE — PRODUCT PROOF REQUIRED`. |

## Difference from nearest prior angle

The nearest prior angle is `quantity-basis`, which distinguishes requirement, planned purchase, actual use, leftover, reserve, unit, source, date, and status for quantities. `value-state` changes the pain to **whether a field’s absence or invalidity is being mistaken for a valid number**. The hook changes to **“Blank is not zero.”** The visual metaphor changes from quantity cards to a field-state strip showing `RECORDED / DERIVED / PLANNED / NOT PROVIDED / NOT APPLICABLE / INVALID / UNVERIFIED`. The proof surface changes from quantity context to a current value-context surface with field/value/state/unit/source/date/validation/notes and exact interaction semantics. The emotional turn changes from traceable quantity basis to honest uncertainty before calculation. The final line changes to **“Name the value before you calculate from it.”**

It is distinct from `default-state` because it is not about inherited or default-filled choices; from `basis-label` and `decision-ledger` because it is not about classifying a number for a business decision; from `measurement-provenance` because it is not primarily about where a measurement came from; from `grade-transparency` because it is not about why a size changes; from `data-minimum` because it is not about which fields are required; from `focus-path` because it is not pointer/keyboard reachability; and from `recovery-proof` because it is not restoration. It does not reopen or reuse `false-completion` or `release-gate-roster`.

## Treatment and production bible

Open on an original abstract field card marked `ILLUSTRATIVE — NOT PRODUCT UI`. The field reads `VALUE: —` and the narrator refuses to call it zero. A second card introduces `NOT PROVIDED`, then `NOT APPLICABLE`, then `INVALID`, then `DERIVED`, then `RECORDED`. The cards end with `SOURCE / DATE / VALIDATION / NOTES` before the final blocker card `VALUE STATE VISIBLE — PRODUCT PROOF REQUIRED`.

A current Stitch & Scale value-context capture may replace the fictional cards only if a current, approved, non-private proof registry entry verifies exact labels, state semantics, product version/date, and rights to show the capture. A still image cannot prove data-shape semantics, null-versus-zero preservation, or invalid-input behavior; those require interaction/data evidence. If proof is absent, retain the blocker card and disclaimer.

Use one narrator family. David may appear only with authorization and remains described as a developer whose late mother knitted; he is not a knitter, knitwear designer, pattern designer, or technical editor. Captions must not cover field cards, values, state labels, units, sources, dates, validation warnings, hands, menus, logos, or CTA. Review caption-on and caption-free versions. Generated text remains illustrative and cannot substitute for current product labels or data evidence.
