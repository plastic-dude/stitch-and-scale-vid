## Core creative distinction

The nearest prior is pass 251 `maker-entry-state`. Pass 251 asked what minimum context must be visible before a maker begins. Pass 252 asks how a later change should communicate its delta to people who may already be working from an earlier state.

| Dimension | Pass 251 `maker-entry-state` | Pass 252 `version-delta-state` |
|---|---|---|
| Changed pain | Entry-state blindness before work begins. | Silent-delta debt after the work has already started. |
| Hook | “Before you start, what exactly do you have?” | “A correction is not complete until the people using the old version can see what changed.” |
| Visual metaphor | Seven-field entry card unfolding from identity to scope. | From/to delta card with an affected-surface strip. |
| Proof surface | Pattern ID/version, materials, gauge basis, notes, size/measurements, support files, scope/limit, entry review, human choice remains. | From version, to version, change type, affected surface, old state, new state, why, sizes/representations, action required, evidence, owner, status. |
| Emotional turn | False readiness replaced by a named entry boundary. | Silent replacement replaced by explicit delta communication. |
| Final line | “Start with the information, not the assumption.” | “Name the change before you ask anyone to trust the new version.” |

The angle is not a rename of `change-notice`, `change-communication-state`, `version-lock`, `drift-state`, `revisitability-state`, `derived-freshness-state`, `ambiguity-state`, `maker-entry-state`, `review-question-state`, `false-completion`, or `release-gate-roster`. It has no automatic version comparison, correction propagation, tester notification, release roster, or release approval surface. Generic human-gate proof does not authorize the imported roster.

## Dramatic engine before camera

**Subject:** A fictional `VERSION DELTA` card comparing two pattern states.  
**Desire:** Let a designer or tester know exactly what changed before reusing earlier notes, samples, or conclusions.  
**Obstacle:** A new file can look cleaner while the affected row, chart, size, material, or representation remains unnamed.  
**Stakes:** Prior notes may no longer apply; the video must not claim this happened to a Stitch & Scale user.  
**Change:** Move from silent replacement to `FROM_VERSION / TO_VERSION / AFFECTED_SURFACE / ACTION_REQUIRED`.  
**Contradiction:** A correction can make the new pattern better while making old evidence unsafe to reuse unless the delta is visible.  
**Escalation:** From/to versions appear; one change category appears; affected sizes or representations appear; the old state and new state separate; action required remains human-reviewed.  
**Final image:** `V001 → V002 / CHANGE TYPE / AFFECTED SURFACE / OLD STATE / NEW STATE / WHY / ACTION REQUIRED / EVIDENCE / OWNER / STATUS: HUMAN REVIEW` with `ILLUSTRATIVE — NOT PRODUCT UI`.

## Treatment

Open on a clean desk with a paper card titled `VERSION DELTA`. The narrator says, “A correction is not complete until the people using the old version can see what changed.” The top card reveals `FROM: V001` and `TO: V002`. A middle strip shows one fictional category at a time: `CHANGED / CHART C-01 / ROWS 1–12`, then `AFFECTED SIZES / REPRESENTATIONS`, then `ACTION REQUIRED / RECHECK`. The lower fields read `WHY`, `EVIDENCE`, `OWNER`, and `STATUS: HUMAN REVIEW`. The narrator explains that a change notice is not automatically a defect verdict, a universal correction, or release approval. The founder turns the paper away and says he will not pretend it is the app. The final card invites founding testers to identify what the current product can actually preserve when a pattern changes after work begins.

## Visual grammar and production bible

Use one narrator family, one tabletop, one paper system, one charcoal/cream/ink-blue palette, and a strict type hierarchy. The only readable words are the fictional labels listed in this brief, with the fixed footer `ILLUSTRATIVE — NOT PRODUCT UI`. Do not render real pattern lines, stitch counts, row counts, abbreviations, chart symbols, schematic measurements, tester identities, customer records, or UI controls. Generated text is not UI truth. Any future product number, label, warning, or control must come from a current approved capture.

The primary location is a quiet desk with no private documents. Use one locked overhead camera and one 45-degree macro angle. Keep the delta card within a high-contrast central area. Use one change category per close shot, one affected-surface label, and one action boundary. No digital auto-refresh, fake notification, fake save, fake database, or effect may imply product behavior. No paper flip may suggest that a prior version vanished.
