## Concept and distinctness

A claim can be carefully worded and still point at the wrong artifact if “latest” replaces the exact capture, source note, or output that was actually reviewed. The nearest prior angle is `authority-state`, which concerns which field controls an output. `version-lock` changes the pain to a claim or review pointing at the wrong artifact state. The hook becomes “Current is not the same version.” The visual metaphor changes from a source-to-output dependency map to a claim card anchored to a frozen snapshot while a latest card changes. The proof surface is `ARTIFACT ID / VERSION OR SNAPSHOT / CAPTURED AT / REFERENCED AS / CHANGED SINCE / SUPERSEDES / USES / OWNER`, explicitly illustrative until product proof exists. The emotional turn is from citation anxiety to bounded evidence confidence. The final line is “Bind the claim to the version you actually saw.” It does not recreate `capture-freshness`, `supersession-state`, `review-expiry`, `retention-state`, `provenance-chain`, `authority-state`, `commit-state`, `export-portability`, imported `false-completion`, or imported `release-gate-roster`.
