## Concept and distinctness

A waiver can be a bounded decision to accept a named deviation, but it is not proof that the original requirement was met. The nearest prior angle is `review-expiry`, which focuses on review-window obligation and its basis. `waiver-state` changes the pain to a deviation being mistaken for satisfaction of the original requirement or permission to erase it. The hook becomes “Waived is not met.” The visual metaphor changes from a review-window card to a layered requirement/deviation record with the original requirement still visible. The proof surface is `REQUIREMENT / DEVIATION / SCOPE / RATIONALE / AUTHORITY / CONDITIONS / COMPENSATING ACTION / EXPIRY OR REVIEW / RESIDUAL STATE / STATUS`. The emotional turn is from making review obligations explicit to preserving what remains unmet. The final line is “Name what remains unmet when you record the waiver.” It does not recreate review-expiry, drift-state, exception-scope, risk-trigger, failure-mode, acceptance-criteria, decision-reversal, outcome-proof, false completion, release roster, or a human release checklist.
