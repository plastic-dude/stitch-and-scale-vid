## Concept and distinctness

A later withdrawal may change what can happen next, but it does not silently prove erasure of every asset, retroactive invalidity of every prior use, termination of every license, or automatic product enforcement. The nearest prior angle is `consent-state`, which focuses on purpose- and use-bounded permission before use. `withdrawal-state` changes the pain to a later withdrawal being treated as either irrelevant or as automatic erasure of every downstream use. The hook becomes “Withdrawn is not erased.” The visual metaphor changes from a granular consent/rights card to a downstream-impact map branching from a withdrawal event into affected uses, assets, actions, retention, and status. The proof surface is `CONSENT STATE / WITHDRAWN AT / AFFECTED USES / DOWNSTREAM ASSETS / STOP-USE ACTION / ERASURE REQUEST / RETENTION BASIS / OWNER / STATUS`. The emotional turn is from narrowing permission before use to confronting what changes after permission changes. The final line is “Name what changes when permission changes.” It does not recreate consent-state, rights-scope, review-expiry, decision-reversal, supersession-state, response-state, outcome-proof, provenance-chain, false completion, release roster, or a human release checklist.
