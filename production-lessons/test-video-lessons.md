# Test Video Lessons — Required Prevention Rules

The supplied test video is approximately 103 seconds at 1280×720, 30 fps, with mono AAC audio. It uses a specific knitwear workflow script, but its large captions cover the central product table and obscure the proof the narration asks viewers to trust.

## Do not repeat these failures

Captions must remain inside a declared safe zone and must never cover faces, hands, tables, numbers, buttons, menus, logos, or primary actions. A caption-free review and a caption-on review are both mandatory.

Do not stack large narration captions, small editorial statements, native UI labels, and generated callouts without a strict hierarchy. Generated text is not product truth; use approved captures or post graphics for numbers, labels, and claims.

A dense full-screen table is not mobile proof. Use an establishing shot followed by close, readable proof shots showing one measurement family, one warning, or one state change at a time.

The user reported mixed voices. Automated transcription found one continuous narration, but mono audio and a transcript do not prove speaker continuity. Every Generator run must declare one narrator family or an explicit speaker map and must listen for voice-model drift, doubled words, overlap, accent changes, room-tone jumps, and inconsistent mic distance.

The script was more specific than generic SaaS copy, but it still behaved as a feature tour. A new script must dramatize one high-stakes designer pain, reveal a contradiction, show a verifiable proof moment, and end with an honest tester invitation.

Reject and regenerate rather than covering defects with extra captions, music, effects, or transitions. Keep Git for scripts, briefs, manifests, and QA; store full-resolution MP4s in the external media archive.
