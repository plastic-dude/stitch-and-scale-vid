## Selection result

`size-exception-state` was selected after refreshing the published branch and inspecting the 266 occupied ledger rows. No row used this exact slug. The candidate is reserved once in this pass and does not reuse or rename any prior filename.

The fresh question was: **When a graded pattern reaches an edge case where a default rule no longer preserves the intended fit or relationship between body points, what should be recorded so the exception is visible and reviewable rather than silently extended?** The research changed the concept from generic size coverage to a visible breakpoint between a default rule and a design-specific exception.

## Nearest prior and material difference

The nearest prior is pass 248, `size-coverage-state`, with pass 254 `dependency-disclosure-state` as the immediate recent-state neighbor. Pass 248 asked whether each promised size had evidence coverage. Pass 256 asks what happens **inside a covered size range** when the default grading rule stops being sufficient.

| Dimension | Pass 248 `size-coverage-state` | Pass 256 `size-exception-state` |
|---|---|---|
| Changed pain | A size can appear in a range without evidence that it was actually covered. | A covered range can still hide a breakpoint where the default rule no longer explains an affected piece or body point. |
| Hook | Coverage and evidence behind every size. | “A size range can be complete while one rule quietly stops making sense.” |
| Visual metaphor | Size-by-size coverage roster or evidence matrix. | A paper grading ruler hits a marked breakpoint; `DEFAULT RULE` flips to `EXCEPTION: HUMAN REVIEW`. |
| Proof surface | Size, evidence source, coverage state, human size review, status. | Size, body point, default rule, exception, affected pieces, why, maker note, technical edit, test knit, status. |
| Emotional turn | A complete-looking range becomes accountable to evidence. | A smooth-looking rule becomes honest about its edge and stops pretending to be universal. |
| Final line | “Show me the size nobody checked.” | “Show me where the rule stops—and who reviews the exception.” |

The candidate is also distinct from occupied `size-boundary`, `size-coverage-state`, `grade-transparency`, `fit-criteria-state`, `gauge-state`, `decision-conditions-state`, `substitution-authorization-state`, `derived-freshness-state`, `exception-state`, and `decision-ledger`. Those concepts address general boundaries, coverage, grade visibility, fit criteria, gauge, conditions, substitutions, stale derivations, generic exceptions, or business-number classification. Pass 256 focuses on a grading breakpoint and its affected construction relationships, not on a size roster or a generic status.

## Dramatic engine choice

**Subject:** A fictional paper `SIZE EXCEPTION` card and ruler.
**Desire:** Make the point where a default grading rule stops being trustworthy visible to a designer and reviewer.
**Obstacle:** A polished range can hide a design-specific change in body point, ease, length, sleeve, neckline, armhole, or shaping relationship.
**Stakes:** A maker may follow a rule that was not intended for the edge case. The film must not claim this happened to a Stitch & Scale user or that the product prevents it.
**Change:** Move from a smooth default line to a labeled exception with affected pieces and separate human review gates.
**Contradiction:** More sizes do not automatically mean more explanation.
**Escalation:** Default rule appears; ruler reaches breakpoint; exception appears; affected pieces appear; technical edit and test knit remain separate; status becomes hold.
**Final image:** `DEFAULT RULE → BREAKPOINT → EXCEPTION / HUMAN REVIEW`, with `ILLUSTRATIVE — NOT PRODUCT UI`.
